# Generate migrations from Java

`MigrationDirectory` writes the same migrations as the protoc plugin, from a `Schema` that you build in Java.
Use it when your tables are not protobuf messages, or when your own tool writes the migrations.

## Steps

1. Add the dialect module of each database.
   Each one brings `leadseal-dialect`:

   ```xml
   <dependency>
     <groupId>dev.horizon</groupId>
     <artifactId>leadseal-dialect-postgres</artifactId>
     <version>0.3.1-SNAPSHOT</version> <!-- x-release-please-version -->
   </dependency>
   ```

2. Build the columns.
   Give each column a stable id, because leadseal matches columns by id:

   ```java
   Column id = Column.of("1", "id", new IntegerType(IntegerType.Size.INT64), NotNull.INSTANCE, Identity.INSTANCE);
   Column state = Column.of("2", "state", TextType.of(20), NotNull.INSTANCE, new LiteralDefault("new"));
   ```

3. Build the tables and the schema:

   ```java
   Table orders = Table.of("shop.Order", "orders", List.of(id, state), PrimaryKey.of("orders", List.of("id")),
       Index.of("orders", List.of("state"), false), new Comment("The orders of the shop."));
   Schema schema = Schema.of(new Namespace("sales", List.of(orders)));
   ```

   `Schema.of(orders)` puts the tables in the default database schema of the connection instead.

4. Generate the migration:

   ```java
   MigrationDirectory migrations = new MigrationDirectory(Path.of("src/main/resources/db/migration"),
       List.of(new PostgresDialect()));
   MigrationPlan plan = migrations.generate(schema);
   ```

## Check the result

`plan.migration()` is the folder of the new migration, or empty when the schema did not change.
`plan.files()` lists the files that `generate` wrote:

```text
snapshots/681036ec15495490/contract.json
20261104092938/migration.json
20261104092938/postgresql/V20261104092938.sql
```

The SQL file contains:

```sql
CREATE SCHEMA IF NOT EXISTS "sales";

CREATE TABLE "sales"."orders" ("id" bigint GENERATED BY DEFAULT AS IDENTITY NOT NULL, "state" varchar(20) NOT NULL DEFAULT 'new', CONSTRAINT "pk_orders" PRIMARY KEY ("id"));

CREATE INDEX "ix_orders_state" ON "sales"."orders" ("state");

COMMENT ON TABLE "sales"."orders" IS 'The orders of the shop.';
```

## Read protobuf files

To read table messages in Java, add `leadseal-protobuf` and use `ProtoSchema`:

```java
Schema schema = new ProtoSchema().read(List.of(Shop.getDescriptor()));
```

`Shop` is the outer class that protoc generates for `shop.proto`.

## Get the files without writing them

Call `plan` instead of `generate`.
It returns the same `MigrationPlan`, and you write each `MigrationFile` yourself with `file.write(directory)`.

## Find a dialect by name

`Dialect.of("postgresql")` finds an installed dialect module with `ServiceLoader`.
It throws `ConfigurationException` when no installed dialect has the name.

## Set the clock, the prefix or the unsafe changes

Pass `MigrationOptions` as the third argument:

```java
new MigrationDirectory(directory, List.of(new PostgresDialect()), MigrationOptions.defaults().withPrefix(""));
```

`withClock` sets the clock that gives the version of a new migration.
`withPrefix` sets the prefix of temporary objects.
Refer to [Protoc plugin options](protoc-plugin-options.md#temporary-objects).

`allowUnsafe` applies unsafe changes, such as a column type that holds fewer values.
Without it, `plan` and `generate` throw an `UnsupportedChangeException` for an unsafe change.

`MigrationPlan.warnings()` describes the data that the new migration deletes, such as `drops the table orders and its rows`.
Show it to whoever runs the generation.
Refer to [About data loss](about-data-loss.md).
